# Feature parity: Sheaf against Origin (9.3)

A snapshot. Update a row when its feature lands; re-run the audit after each milestone.

Date: 2026-11-12 (first written 2026-11-11; rows brought up to date with the code on 2026-11-12).

This document answers the owner's question: does Sheaf have all of Origin's features? The short answer is no. Sheaf does the owner's daily jobs well, but it has about a third of what Origin offers in some areas and almost nothing in others. Since the first version of this table the app has gained Origin's window arrangement, menus, shortcuts, right-click menus, graph window and several dialogs, and it saves .opj by default, so those gaps are much smaller; what Sheaf still lacks is mostly breadth: matrices, contour and heat maps, 3D, many plot families, most statistics beyond the basic tests, scripting, and the generic analysis dialog.

## How the audit was made

Five auditing agents compared the specs in `docs/spec/` with the Rust code. Status was judged from the code: the agents opened the function and checked that a menu entry, dialog or command-line subcommand reaches it. They merged the several hundred audit rows into the 230 rows below, so one row can stand for several Origin features. The counts therefore count rows, not individual Origin features.

What was not done: nobody built or ran the app or the CLI, so wiring was judged from reading code and not by clicking. Nobody ran Origin through `tools/origin-ref/`, so the Origin side of every row comes from the specs, and many spec items are themselves marked unverified. No test suite was run, so numeric accuracy is only as good as the claims already recorded in the specs.

Update of 2026-11-12: this update was made by reading code on 2026-11-12, again without building or running anything. Each row whose subject the work since the first version touches (app shell, graph window, dialogs, gadget, Data Reader, Copy Page, area, double-Y, stack, column and panel graphs, .opj saving and reading, CH Instruments .bin and chronopotentiometry, import dialog and NLFit dialog) was checked by opening the menu table in `crates/app/src/menus.rs`, the command-line options in `crates/cli/src/args.rs` and the function behind each entry. A row whose feature could not be confirmed that way keeps its earlier status. The rows were not re-checked against Origin.

Statuses: ✓ done, ◐ partial, ✗ missing. Priorities: P0 is the owner's daily work and the owner's explicit requests, P1 is useful, P2 is rare.

By priority alone: 101 rows are P0, 87 are P1 and 60 are P2.

Reading the counts: the P0 rows are mostly present but often only partly (69 of 101 are partial). No P0 row is missing altogether any more: the analysis dialogs now share one frame with Preview and Auto Preview, and the Analysis menu works on a graph's data plot. Since 2026-11-11 the former holes of .opj saving, the Origin look, Double-Y graphs, offset and waterfall plots and graph gadgets have become partial rows: they work for the owner's cases but lack Origin's breadth (three or more Y axes, colour-mapped waterfalls, more gadgets, saving the newer graph features into .opj without the companion file).

Cross-cutting findings:
- Column formulas recalculate (None, Auto, Manual; see workbook-model.md 10a). The CHI import writes `col*1000` formulas that stay one-time values (mode None).
- Analysis and fit results are static sheets, not linked to their source data.
- The core model holds several layers per graph (linked layers carry double-Y and panels) and the graph window edits any layer; a per-plot choice of left or right Y axis is only on the command line.
- `crates/io/src/opj/write` writes workbooks, graphs, column formulas and nested folders as Origin projects. The app saves .opj by default and writes a companion `.opj.sheaf` file for what the writer cannot hold (linked layers, stack offsets, bar gap, area fill, some tick settings, window places); matrices, notes and fit results are not written.
- Many menu entries and toolbar buttons exist only as grey placeholders with Origin's names; they are counted as missing, not as done.

## Order of work

Each stage assumes the earlier ones. (Stages, not the numbered milestones of `docs/ROADMAP.md`.) Effort is not estimated here.

Progress on 2026-11-12, from reading code: in stage 1, steps 2 to 5, 7 and 8 and most of step 3 are in place (date and time columns, batch import, Double-Y, offsets and waterfall, creatable column plots, the Peak Analyzer chain, reference subtraction and curve math, fit bands and controls, recalculating formulas, cell copy and paste); step 1 still waits for the owner's text exports, and step 6 (free text labels, legend options, Origin's colour list, size and margin options, TIFF, EMF, EPS) is open only for Origin's colour list and the margin options (the legend text, columns and drag, EPS and EMF are in place). In stage 2, .opj writing, child windows, toolbars, Origin's menus and shortcuts, the Project Explorer, Plot Details as a tree and the axis dialog are in place; the shared analysis dialog frame (Preview and Auto Preview, no Auto Apply), the Column Properties dialog and the Import Wizard are in Origin's layout since 2026-11-12. In stage 3, t-tests and frequency counts are done; the rest of the stage is open.

**Stage 1. Daily electrochemistry and ICP-OES work (P0 gaps).**
1. CH Instruments: confirm against real CV and i-t files, since the spec says none was checked.
2. CSV and ICP-OES: date and time columns, non-numeric handling, import into an existing sheet or new sheets, thousands separators, parameter rows, and a batch command over folders.
3. Overlay and column plots: make column plots creatable, line-style and symbol increments, X error bars and error-bar options, Double-Y, offset and waterfall plots.
4. Integration and peaks: per-peak integration with a results table, anchor-point baselines, picking limits on a graph, CV charge helper, then the Peak Analyzer chain and multi-peak fit.
5. Subtract reference curve and simple curve math.
6. Publication figures: free text labels, legend options, Origin's default colour list, rescale command, size and margin options, extra image types (TIFF, EMF, EPS).
7. Fitting: expose iteration and tolerance, confidence and prediction bands, initial guesses for more functions.
8. Column formulas that recalculate, and copy, cut and paste of cell ranges.

**Stage 2. The look and feel and .opj saving the owner asked for.**
1. Write .opj files. This needs a format study of the writer side, checked by opening the result in Origin through `tools/origin-ref/`. liborigin may be read for understanding, not copied. Start with workbooks, then graphs, so saved work reopens in Origin.
2. Origin-style chrome: MDI-style child windows, toolbars (standard, edit, graph, column, worksheet data, 2D graphs), Origin's menu names and order (View, Column, Statistics, Gadgets, Tools, Format) and menus that change with the active window.
3. Origin's shortcuts (Ctrl+K, Ctrl+Q, Ctrl+D, Ctrl+R, F2, F4, F12 and others), a Project Explorer with folders, Plot Details as a tree, the generic analysis dialog with Preview and Auto Apply.
4. Layers: a real multi-layer graph UI.

**Stage 3. Everyday gaps (P1).** Gadgets and graph analysis, recent lists, print, options dialog, Excel import and export, templates and themes, row statistics, t-tests and histograms, FFT and the other smoothers, worksheet operations, masking, live filters, simulate curve, plus the remaining P1 rows above.

**Stage 4. The rest (P2).** Matrix and image windows, 3D, contour, specialised plot families, ANOVA, nonparametric and multivariate statistics, global and surface fits, scripting, COM, other importers.
