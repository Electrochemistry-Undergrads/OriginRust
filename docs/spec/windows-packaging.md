# Windows application packaging

## Executable icon (T31)

`sheaf-app.exe` embeds the owner's existing `crates/app/assets/icon/sheaf.ico` as native Windows
resources. The seven frames are 16, 24, 32, 48, 64, 128 and 256 pixels. The runtime window icon
continues to use `sheaf-256.png`; no artwork is regenerated by a normal build.

`crates/app/build.rs` checks Cargo's **target** OS (`CARGO_CFG_TARGET_OS`), rather than the build
host. On Windows targets it compiles `assets/icon/windows.rc` and links the result only to the
`sheaf-app` binary, using `embed-resource = "=3.0.12"` (released 2026-10-06). That helper locates
the Windows resource compiler, including the Windows SDK's `rc.exe`. Other targets skip resource
compilation. The icon and resource description both have explicit Cargo rebuild tracking.

Embedding is required on Windows: a missing/broken resource compiler fails the build with an
actionable error instead of silently producing an executable without the icon. The helper's
`manifest_required()` selects this error policy; the resource file contains only an icon and
does not add a Windows application manifest or change privilege requirements. Resource language
is neutral and the icon group ID is 1.

Primary reference: [embed-resource 3.0.12](https://docs.rs/crate/embed-resource/3.0.12), including
the binary-specific compile API and explicit rebuild tracking.

## Build and verify

With Rust and the Windows C++ build tools/SDK installed:

```powershell
cargo build --release -p sheaf-app
python tools/check-windows-icon.py target/release/sheaf-app.exe
```

The standard-library-only verifier reads the PE resource directory and source ICO. It checks
RT_GROUP_ICON ID 1 and compares every referenced RT_ICON frame's dimensions, size and complete
payload with the source artwork. This can also inspect a Windows artifact from another OS.

Verified on Windows on 2026-11-14 using a native debug build:

- All seven PE frames match the source ICO byte-for-byte.
- Windows `ExtractIconExW` reports one icon group and returns valid large and small icons.
- The verifier rejects a CLI test executable that has no icon resource directory.
- The actual compiled build script returns without resource link arguments when given a
  non-Windows target OS, an unavailable resource compiler and an empty executable search path.
- Hashes of all four source icon artwork files remain unchanged.

The release build uses the same target-gated resource script. No Start Menu installation, file
association or installer is provided here. Those remain separate work.
