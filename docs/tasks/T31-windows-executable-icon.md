# T31: Windows executable icon

**Status:** done on `codex/windows-exe-icon` (2026-11-14, Windows): native icon resources embedded;
all seven frames match the source ICO and Windows extracts both sizes. Formatting, strict
workspace all-target Clippy and 1,973 workspace tests pass (two ignored), on integrated `c045e46`.
**Size:** S. **Source:** HANDOFF's app-icon owner request (2026-11-14).

## Goal

The built `sheaf-app.exe` has Sheaf's existing bronze S in its Windows icon resources, so Explorer
and shortcuts can use the application icon. The running app already embeds the PNG window icon.

## Origin facts

None needed: this is Windows application packaging using the owner's existing artwork. Do not
copy Origin's icon or alter Sheaf's branding assets.

## Where

- New `crates/app/build.rs` and a resource description if required.
- `crates/app/Cargo.toml` build dependencies only; `Cargo.lock` if a helper is needed.
- Input: `crates/app/assets/icon/sheaf.ico` (generated by `tools/make-icon.py`, read-only here).
- New built-PE verification helper and a Windows packaging spec paragraph.

## Steps

1. Read the chosen helper's primary documentation. Prefer a small maintained build helper,
   pinned to an exact release at least two weeks old; use a dependency already in the lock when
   practical. Run resource compilation only for a Windows target; other targets keep building.
2. Embed the existing multi-size `.ico`, with Cargo rebuild tracking for the icon/resource input.
   Report a useful build error if the Windows resource compiler cannot be found.
3. Build the native executable and verify its PE resource directory contains a group icon and
   the icon frames from the source `.ico`. Exercise Windows icon extraction if available.
4. Run formatting, strict workspace all-target Clippy and the workspace tests; commit and push.
   Record the build/verification commands and update this Status and HANDOFF.

## Done when

The native Windows executable contains the expected icon resources, the source artwork is
unchanged, and the required checks pass. Native resource verification must inspect the actual
executable, rather than merely checking that the source/build script contains an icon path.

Validation used a native debug executable. The verifier rejected a no-icon CLI test executable;
the actual build script skipped resource work for a non-Windows target with the resource compiler
unavailable. All source artwork hashes remained unchanged. Details and repeatable commands are in
[`windows-packaging.md`](../spec/windows-packaging.md). Release uses the same resource script.

## Don't

- Do not install Start Menu shortcuts, change file associations or touch another session's app
  dialog, printing, clipboard or autosave code.
- Do not replace the runtime PNG window icon or generate new artwork.
- Do not require Windows resource tools when building for non-Windows targets.
